## Portable module boundary

The new `nold-ai/specfact-workflow` package registers `workflow` through existing core module discovery. It owns orchestration and bundled reusable `specfact-*` workflow skills; repository adapters supply gate commands, applicability and optional governance integration. Reuse existing module interfaces and declare dependencies/compatibility in the manifest. Do not hardcode these repositories, Hatch, an internal wiki or a model provider into the deterministic engine. Public APIs use icontract/beartype contracts; module signing and registry publication use existing release tooling.

R09 owns Requirements v3 reconciliation of supplied plan/test metadata. Workflow execution is separate and does not add I/O to that reconciler. Preserve original Requirements, Code Review and independent security outputs. Code Review 1.6 is not a general gates envelope: extra fields may be ignored and timestamps vary. C15 alone owns calibrated blocking policy. Unsupported required schema/policy is non-passing with an install/compatibility diagnostic, not a fallback PASS. Governance envelopes and graph adapters remain future consumers of local state, not duplicate contracts here.

## Command behavior

| Surface | Behavior |
| --- | --- |
| `workflow pre-validate --change ID` | Validate current change inputs and configured readiness; emit drift observations and required blockers without editing plans. |
| `workflow implement --change ID --begin/--checkpoint/--status` | Begin/resume one local run, record scoped verification and account for repair attempts; agent owns source edits. |
| `workflow verify --change ID --scope index/worktree/range` | Standalone current verification; range requires explicit `--base-ref`/`--head-ref`, resolved to immutable commits; default scope is worktree. A fast selection never claims full verification. |
| `workflow fix --run ID --recheck` | Present ordered current findings and rerun affected configured gates; repair is performed by an explicitly invoked agent or native fixer. |
| `workflow autofix --pr NUMBER` | Observe CI plus reviews by default; explicit mutation capabilities enable local repair, publishing or thread resolution. |

`implement --begin` performs current pre-validation itself (or verifies an identity-matching current result), checks mutation/worktree governance and starts its budget. It does not require an earlier user session to have produced a receipt. Checkpoints refer to that run for budget accounting; standalone verify always remains available.

Commands return 0 only for the requested satisfied checks, 1 for actionable findings, 2 for blocked/unknown/invalid input and 3 for exhausted budgets. JSON carries explicit check selection and producer statuses; exit zero for a fast check is not full delivery acceptance. Missing required tools are blocked; optional producers are visibly not evaluated. No LLM is needed for pre-validation, verification or fix planning. Recheck selects every gate affected by the actual edits through declared input applicability, not just the original failing producer; uncertain applicability falls back to the configured complete lane.

Check adapters use argument arrays, controlled working directories and timeouts. Never run the mutating aggregate pre-commit script as verify. Preserve source/index contents; ignored receipt/cache output is allowed. Reuse existing outputs only for matching scope/content/config/tool identity and complete current required results. Capture and compare inputs before/after execution; concurrent changes invalidate the result rather than passing a mixed snapshot. Index checks use an isolated materialization of index content; worktree and range have explicit manifests including deletions, modes and relevant untracked inputs. Do not check out over user changes.

## Local state and reproducibility

Use ignored `.specfact/turn/<unique-run-id>/` with a schema-version-1 local receipt and references/digests for original producer artifacts. Keep the normalized findings view separate from ReviewReport serialization; every projected item retains producer, original rule/severity, source artifact and identity. Projection cannot decide a producer verdict. The receipt records run/phase, selected inputs, check outcomes, budgets, timestamps and artifact references. It is disposable operational state, not a new general evidence envelope or required committed ledger.

Input identity includes repository identity, resolved base/head where relevant, exact scope manifest (index/worktree content, relevant untracked files, modes/deletions), reviewed planning inputs, effective policy/configuration, selected commands and relevant tool/module/environment identities. Exclude generated receipt/cache paths from source identity, not arbitrary untracked source. Do not hash secret environment values into public artifacts; only explicit non-secret relevant configuration is retained. A unique run ID is not the input digest. Two dirty trees at one HEAD must have different content identities.

Compare a canonical semantic projection for deterministic adapters; timestamps, durations, unique run IDs and live-service observation times are excluded. External observations carry their snapshot/version and time. Replaying a frozen observation can reproduce its evaluation, not today's GitHub state or stochastic model text. Receipt writes use atomic replacement and one per-worktree controller lock. Resume verifies current identities and reconciles incomplete operations; missing local state starts a new standalone verify and never blocks ordinary CI. A local receipt cannot prevent arbitrary shell actions outside this CLI or authenticate itself for protected CI.

## Drift and optional assurance

Use explicitly bound reviewed plan/spec/task inputs, not the most recent folder commit, as the comparison baseline. Distinguish missing MODIFIED targets from legitimate new ADDED capabilities. Changed paths, renamed references and closed/reopened blockers are observations with suggested disposition; they are not automatic semantic invalidity. Check uncovered native issue governance in the adapter; backlog verify-readiness alone does not prove parent/label/project/concurrency completeness. Offline local checks remain useful, while a required unavailable live check stays unknown. Internal wiki absence is a configured repository follow-up only.

Optional preflight/seal/conformance is invoked only when explicitly selected and retains its own stricter input, signature and authority requirements. Ordinary workflow state is never presented as a substitute approval seal. Current-run Requirements context never rewrites independent review/security verdicts.

## Bounded local and PR repair

Default limits: three local repair iterations; five PR repair rounds; 60-minute elapsed budget per run, 15-minute subprocess timeout and 60-second PR polling interval. Explicit positive overrides are recorded at run start; a resumed run retains consumed counts and elapsed time. Read-only polls do not consume repair rounds but do consume the time budget. Reserve a repair attempt before invoking a fixer, so crashes do not reset the budget. On cancellation or timeout terminate the process group, retain diagnostics and leave the result non-passing.

Stop early after a repair leaves both content and normalized blocking findings unchanged; stop oscillation when a previously seen content/findings pair recurs. Remaining findings or pending checks at the time/round limit produce an actionable stop, not success. The immutable selected input and effective producer policy decide which findings require remediation; the loop does not invent an error-only exception to contributor governance.

PR automation is local (`gh` plus an explicit Codex exec adapter), never a privileged CI agent. Default is observation. `--apply` permits scoped local edits, `--publish` additionally permits normal commits/pushes, and `--resolve-threads` additionally permits evidence-backed replies/resolution; the latter two require apply. Require a clean owned branch/worktree at mutation entry; subsequent writes must match only this run's authorized pending changes. Revalidate exact repository/PR head before each external write. Existing user changes, another controller or an unexpected remote head stop mutation for reconciliation. Never force-push, merge, change branch protection or escalate tool privileges. Review text and check logs are untrusted data, not shell instructions or authority to widen scope.

Persist a stable operation key and pending intent before externally visible writes; on restart read back branch, comments and thread state before deciding whether to retry. An uncertain push/comment outcome is reconciled, not blindly repeated. Recheck the remote head before publishing or resolving a thread. Treat pending CI (`gh pr checks` pending status included) separately from failure, and classify infrastructure/tool outages separately from code defects. Completion requires required checks at the current head, completion of required review sources, and no unresolved actionable review threads. Unknown or unavailable required review status remains pending/blocked. Resolve only an individually verified, fixed finding with a commit/check reference; stale/outdated is not proof of resolution. Paid review triggers are not automatic.

Implement one reviewable slice at a time: reusable skills/core projection; deterministic adapters/state; bounded local repair; PR observation then authorized writes. Skills reference available commands only and do not activate planned runtime surfaces. Use frozen test repositories and mocked GitHub/Codex boundaries before a real pilot. Open and integrate bounded PRs before signed publication and trusted adoption. Publish a compatible signed producer without depending on core adoption; core subsequently pilots the exact release. Disable the optional loop and restore its prior pin/config on false PASS, unexpected mutation or duplicate external effects. Do not delete original artifacts or discard user changes during rollback.

## Risk-first guidance in the existing skills

This is a guidance amendment, not an extension to runtime/report/receipt interfaces. Keep canonical reusable guidance in modules and repository wrappers/projection in core. Reference `docs/agent-rules/INDEX.md`, `40-openspec-and-tdd.md`, `50-quality-gates-and-review.md` and `60-github-change-governance.md` rather than copying their policy. Each repository owns applicability and actual commands. Core projection references the modules-owned content; do not hand-copy a second canonical body.

| Existing skill | Added responsibility |
| --- | --- |
| `specfact-pre-validate` | Identify one or two approach-invalidating assumptions for nontrivial behavior changes; record planned observable checks, obligations and exclusions in existing sections. Use a brief applicability rationale for documentation-only work. |
| `specfact-implement` | Execute the smallest relevant existing probe before work that depends on its assumption. Record inputs/evidence and the exercised boundary. A disproved assumption returns dependent work to design; an unsupported probe leaves it unresolved. Continue independent work without presenting the dependent approach as ready. Preserve spec -> tests -> failing evidence -> code -> passing evidence. |
| `specfact-verify` | Run required verification on current bound inputs, preserving source/index bytes and independent producer outcomes. A narrow passing probe proves only its exercised boundary; failed/unavailable required producers remain non-passing. Fresh-session verification requires no earlier receipts. |
| `specfact-fix` | Triage with the violated requirement or concrete invariant, reachable failure path and supporting evidence; distinguish confirmed defects, disproved concerns, suggestions and unresolved claims. Model agreement is supporting context, never proof. Preserve producer authority and effective remediation policy. |
| `specfact-autofix` | Keep one writer, batch compatible corrections and pass compact delta/evidence handoffs within existing authority/budgets. Rebind affected verification after changes and broaden review for boundary drift or uncertain impact. Preserve exact-head external-write safeguards. |

Supply assumptions, observed evidence, affected obligations and exclusions to the applicable existing review. No additional default review lane is introduced. A confirmed required defect stays actionable; a preference may receive an evidenced disposition, but disposition cannot waive a required finding under effective governance or alter its producer's verdict. Unsupported claims remain unresolved until evidence or the owning policy supplies a decision.

Correction handoffs reuse existing notes/producer artifacts: delta, affected assumptions, remaining findings and original evidence references. They are not a new packet format. Broaden review when a public/assurance/persistence/signing/compatibility boundary changes or dependency impact is uncertain. Compact handoffs do not reduce final candidate coverage: recheck every affected gate or use identity-matching valid outputs; select the complete lane when applicability is uncertain. One controller retains consumed elapsed/attempt budgets across implementation, optional preflight and PR repair; a handoff/session cannot reset them.

## Bounded evaluation of delivery overhead

Use existing CI timings, producer artifacts and available provider/session records; introduce no ledger, report fields or automatic collection. Token counts by available category (for example input/output/cache) and actual billed charges are different measures. Elapsed time, active engineer effort and waiting are also different measures; record units, source and unavailable values as unknown. Do not convert elapsed time or tokens into labor or money without defensible data.

After the skills/projection slice, review investment at two engineer-days. Run one bounded trial on the next subsequently authorized nontrivial change per repository under existing budgets; compare early discoveries, later escapes, correction batches and observed overhead. Trials are operational evidence, not causal savings proof. Stop/reassess if added ceremony outweighs the observed benefit. Disable/revert guidance/projection if needed while preserving evidence and ordinary checks; existing runtime configuration/module-pin rollback and signed acceptance remain unchanged.
