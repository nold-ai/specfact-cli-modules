## ADDED Requirements

### Requirement: Preserve required review authority
The workflow SHALL schedule diagnostics only after a failed attempted PR independent review and both original failure projections and SHALL preserve its command, environment, full analyzer selection, member deadlines and failure result. Following the completed original 300-second observation, the required whole-CLI parent deadline SHALL be 600 seconds; expiration SHALL remain a failed exit 124.

#### Scenario: Any diagnostic outcome
- **WHEN** the replay completes, fails, times out or cannot start
- **THEN** its result is non-accepting and the original required review remains failed

### Requirement: Authenticate before observation
The helper SHALL verify core version, installed module signatures with the established key, installed reviewer payload, immutable registry reference and fixed staged subject before subject execution. The inline controller SHALL authenticate an immutable helper before execution and SHALL never execute a candidate-workspace helper.

#### Scenario: Unverified identity
- **WHEN** any binding fails verification
- **THEN** no diagnostic subject process starts and only a static unavailable result is public

### Requirement: Restrict public projection
The helper SHALL emit only bounded numbers, static codes and verified installed symbol identifiers. Raw stacks, paths, process identities, argv, environment and errors SHALL remain private.

#### Scenario: Untrusted profile content
- **WHEN** a profile contains foreign same-suffix files, subject functions, secret markers, changed installed files, malformed data or oversized data
- **THEN** no unverified text is emitted

### Requirement: Own observation processes
The helper SHALL bind processes by start identity and ancestry, clean up owned descendants on completion, cancellation and timeout, and report missing joins and coverage as gaps. Cleanup SHALL rescan adopted descendants after parent exit. An 840-second optional allowance SHALL reserve 310 seconds before launching the full 300-second review; insufficient time SHALL refuse launch with a deadline gap.

#### Scenario: Incomplete process evidence
- **WHEN** a PID is reused, a request join is missing or a descendant is unsampled
- **THEN** attribution stays unknown and the result is partial or unavailable

#### Scenario: Host controller proofs
- **WHEN** a regression proof requires a host shell, isolated host interpreter or process lifecycle primitives unavailable to sealed subject programs
- **THEN** both mandatory ordinary-host test routes execute it with unchanged assertions and parametrized cases, while portable privacy controls remain in unit discovery

#### Scenario: Existing-run metadata
- **WHEN** the existing trusted preparation or failure projection observes authenticated prepared source or member evidence
- **THEN** public metadata contains only authenticated source digests, fixed member/side/reason enums and bounded counts, while actual loaded-adapter and effective-deadline authority remain unavailable unless directly bound

### Requirement: Preserve immutable original reports
The workflow SHALL capture the original candidate and independent required report before optional processing, with a private exclusive 0600 copy, no-follow stable regular-file read bounded to 32 MiB plus one probe, complete SHA-256 and size, and an atomically published manifest bound to role, event head and invocation. Repeated capture SHALL reuse only the same binding and verified bytes. Missing, oversized, changing or unreadable originals SHALL remain explicit; failed capture SHALL prohibit the candidate optional overwrite without changing the required exit. Independent replay SHALL retain its existing distinct attempt destination. Raw copies SHALL never be uploaded.

#### Scenario: Replay B follows original A
- **WHEN** the existing optional candidate helper replaces its fixed report destination
- **THEN** public projection remains bound to original A and failed capture prevents that replay

#### Scenario: Capture owner result controls every original consumer
- **WHEN** original capture is rejected, fails to publish, or is skipped for this required invocation
- **THEN** all four original-report readers reject before opening either manifest or raw report, regardless of surviving COMPLETE artifacts
- **AND** only the actual capture command success enables admission through an explicit exact true scalar; absent, false or unexpected values deny admission
- **AND** independent cleared-environment transport and later-step outputs preserve that result without altering the required exit or call count
- **AND** candidate replay requires the original required capture success before reading the preserved manifest; missing captures and unavailable observer context retain their existing prohibitions
- **AND** legacy direct report paths retain their existing behavior

#### Scenario: Rejected original capture in failure projection
- **WHEN** any candidate or independent primary or failure projector receives original bytes with a missing, non-COMPLETE, duplicate-key, digest-mismatched, size-mismatched, oversized or unreadable manifest or capture
- **THEN** it keeps the selected report path unchanged, rejects capture admission, and does not parse or project report bytes or any synthetic fallback file
- **AND** primary projectors emit original_capture_unavailable, the candidate failure projector emits candidate_report_unavailable, and the independent failure projector retains unavailable report evidence without claiming the source is missing
- **AND** the original required exit and primary analysis_timeout output remain unchanged
- **AND** valid COMPLETE captures and readable legacy reports retain their public diagnostics, while genuinely missing legacy reports retain their existing missing behavior

### Requirement: Observe only authenticated loaded host functions
Before chdir the controller SHALL authenticate installed reviewer 0.51.2 and canonical payload d4bcfd8db105c60440b3bdefbe414f1dc148a75c21b8533801d43d888b3d0df4 using the existing pinned key. It SHALL bound runner reads to 2 MiB and compile the whole authenticated module once without execution, using `dont_inherit=True`, its actual filename and interpreter optimization. A bounded type-sensitive recursive comparison SHALL cover code fields, nested constants, position and exception tables. Admission SHALL require exact plain functions, defaults, module globals, origin and five runner aliases: `_materialize_claimed_project_runtime`, `_prepare_capsule_runtime`, `_run_bound_snapshot_pair`, `_dispatch_capsule_member` and `_execute_capsule_member`. This establishes only those loaded host code objects, not transitive globals or guest identity. Decorated launcher observation is excluded.

#### Scenario: Unchanged metadata with replaced code
- **WHEN** bytecode, nested code, defaults, aliases or module ownership differ despite unchanged names and filenames
- **THEN** observation is unavailable and the stock required invocation runs once unchanged

### Requirement: Bound non-authoritative host receipts
The parent SHALL bind event head, checked-out workflow blob and separately computed generated controller SHA-256 in a private manifest before launch. A controller self-hash alone SHALL NOT establish provenance. Receipts SHALL use an exclusive 0600 non-inheritable descriptor in a fresh 0700 directory directly below TRUSTED_ROOT, outside subject, home, tmp, cache and every actual mount source; no descriptor SHALL be passed to children. Wrappers SHALL forward the original argument objects exactly once and preserve the exact return or BaseException. Field extraction, writes, partial installation and restoration failure SHALL NOT replace producer outcomes. Restoration SHALL replace only owned wrappers; foreign replacements SHALL invalidate observation. There SHALL be no threads, retries or per-record fsync. Limits are 128 records, 1024 bytes per record, 128 KiB total and nesting 16.

#### Scenario: Lost final record or malformed ledger
- **WHEN** a write is lost, a tail is partial, nesting is invalid, a binding differs, keys are duplicate/unknown, or completion after successful restoration is absent
- **THEN** the observation is PARTIAL with later_execution_unknown true and no active-at-timeout attribution

#### Scenario: Observation fails during producer unwind
- **WHEN** a producer raises a BaseException while field extraction, write or restoration fails
- **THEN** the identical exception escapes after exactly one producer call

#### Scenario: Optional invocation context is unavailable
- **WHEN** checkout context is absent, the candidate head is not exactly 40 lowercase hexadecimal characters, either run component is not a separately present positive decimal integer, or the joined run identity exceeds 128 characters
- **THEN** no binding or original capture is admitted, no identity is invented, and required preparation and review retain their original arguments, once-only calls and exits (including 0, 2 and 7)

#### Scenario: Optional binding preparation fails
- **WHEN** the candidate workflow Git blob is unavailable, malformed or differs from the checked-out workflow, or directory creation, hashing or exclusive manifest writing fails
- **THEN** readiness remains false, no usable binding or COMPLETE capture is admitted, and required work continues with unchanged enforcement; a genuine required preparation failure still prevents review
- **AND** only successful context validation, Git comparison and private no-follow exclusive 0600 manifest writing enables capture; shell strictness remains enabled with explicit success checks for every optional operation

### Requirement: Publish only fixed diagnostic fields
The added nonhidden artifact SHALL contain exactly schema_version (1), role (candidate/independent), original_status (COMPLETE/MISSING/OVERSIZED/CHANGED/UNAVAILABLE), required_exit (integer 0..255), report_sha256 (64 lowercase hex or null), report_bytes (integer 0..33554432 or null), diagnostic (original_captured/original_unavailable), host_observation_status (AVAILABLE/PARTIAL/UNAVAILABLE), last_observed_host_stage (project_runtime/capsule_prepare/snapshot_pair/member_dispatch/member_execute/UNAVAILABLE), member (the existing ten analyzer ids or UNAVAILABLE), side (base/head/UNAVAILABLE), event (enter/leave/UNAVAILABLE), later_execution_unknown (boolean), loaded_host_identity (null or payload_sha256 and runner_sha256 only), effective_host_timeout_seconds (null), actual_loaded_guest_identity (UNAVAILABLE). AVAILABLE requires valid bound admission and a terminal completion after restoration. No field asserts acceptance. Both reused finding projectors SHALL omit test_function and source/node names while retaining approved outcome/phase/class and existing tracked file/line fields. Discarded native Semgrep coordinates SHALL remain unknown.

#### Scenario: Private test name in original report
- **WHEN** a report identifies a test node also present in tracked source
- **THEN** neither reused public projector emits that node or function name

#### Scenario: Stale or forged textual progress
- **WHEN** the original log contains a recognized Checking capsule analyzer marker before timeout
- **THEN** public timeout output retains exit 124 and analysis_timeout without deriving analyzer/member identity from text
